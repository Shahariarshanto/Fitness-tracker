Privacy Policy

AS Care · Effective date: November 17, 2026 · Last updated: November 17, 2026

This Privacy Policy explains how AS Care ("the App") handles information when you use the AS Care web application at shahariarshanto.github.io/Fitness-tracker. AS Care is a personal exercise, wellness and health self-monitoring tool.

In brief: Cloudflare D1 is the primary data store. The App also keeps a temporary browser cache and pending offline edits. The App provides username/email and password accounts. The Worker requires a valid session token for cloud data access and isolates each account's records. Passwords are stored as salted PBKDF2 hashes; session tokens are stored server-side as SHA-256 hashes. Logout revokes the current session and clears app-owned browser storage. Email verification and password reset are not provided. A persistent login token is stored in browser Local Storage, so protect access to your device.

1. Information you may enter

  • Exercise and movement completion, goals and activity history;
  • Self-reported pain, symptoms, stiffness, fatigue and sleep information;
  • Medication names, schedule labels and adherence checkmarks;
  • Health scores and other self-reported wellness information you choose to enter;
  • Personal dates, notes and other information you choose to record in the App.

This information may be sensitive health-related information. Do not enter information you do not want stored in the Cloudflare D1 database.

2. Where information is stored

Cloudflare D1 (primary storage): The App sends its application state to a Cloudflare Worker, which stores it in a D1 database. The App loads the available saved state and automatically sends changes after a short delay when connectivity is available.

On your device: The browser keeps a temporary cache and pending-change data so the App can start promptly and retry edits after an interruption. Pending offline edits remain on the device until they can be synchronized.

Backups: No automatic cloud backup or independent database snapshot is configured. The App's manual JSON export is the independent backup method. You should periodically export the data and keep the file somewhere safe. D1 is the primary database, not a backup.

3. Access and security

The Worker requires a valid bearer session token for every cloud state request and derives the account ID on the server. D1 records are isolated by account. Passwords are stored as salted PBKDF2 hashes, and server-side session records store only token hashes. Sessions remain active until logout. The browser stores the persistent token in Local Storage; anyone with access to an unlocked device or its browser storage may be able to use that session. Use a unique password and keep your device protected.

Cloudflare provides the database and Worker execution infrastructure and is subject to its own applicable terms and privacy policy.

4. How information is used

Your entries are used by the App to display activity history, progress, symptom summaries and other features you request, and to load and synchronize your application state with Cloudflare D1. The App maintainer does not sell your personal information or use your health entries for advertising.

5. Third-party infrastructure

The App uses Cloudflare Worker and D1 infrastructure to provide its data API and database. Your browser also connects to GitHub Pages to load the application. These providers may process technical information such as network requests, IP address, browser details and service logs under their own terms and privacy practices.

6. Retention and deletion

  • Device cache: remains in your browser until the website's storage is cleared or browser data is reset. Unsynchronized pending edits may be lost if you clear this storage before they are sent.
  • Cloud data: remains in the D1 database until it is deleted through the relevant Cloudflare database controls.
  • JSON exports: downloaded files remain wherever you save or copy them; manage and delete those copies yourself.

Export any data you want to keep before making destructive changes. Clearing browser storage does not itself delete the D1 database record.

7. Security

No internet service can guarantee absolute security. Protect your device, avoid shared or public devices, and keep downloaded JSON exports in a safe location because they may contain sensitive health information. The current API's lack of authentication is a significant limitation.

8. Children

AS Care is not designed specifically for children and is not intended to knowingly collect personal information from children without appropriate permission from a parent or guardian.

9. Changes to this policy

This policy may be updated when the App's features or data practices change. The revised version will be published at this same URL with an updated date.

10. Contact

For privacy questions or requests, contact the AS Care project maintainer through the AS Care GitHub Issues page. Please do not post medical records, personal health details or other sensitive information in a public issue.
